# tadori：次にやることを判断して進める

利用者はこのコマンドだけを覚えていればよい。段階ごとのスキル名や JSON の中身を利用者に意識させない。質問は会話で1つずつ、選択肢があるものは選択肢で聞く。

スクリプトの場所：`${CLAUDE_PLUGIN_ROOT}/scripts`（展開されていなければ、この SKILL.md から見て `../../scripts`）。以下 `$S`。

## 0. 動作確認（毎回、最初に）
```bash
python3 --version
```
失敗したら作業を始めない。次のように伝えて止める：
「この環境には Python 3 がありません。tadori は Cowork で使ってください。Claude Code で使う場合は Python 3 を入れてから再実行してください。」
Python が無いまま進めると、原本の保護やメール宛先の制限が働かないため。

今日の日付を `date +%F` で取っておく。

## 1. いまどこにいるかを判定する
開いているフォルダ（作業フォルダ）を調べ、上から順に最初に当てはまるものを実行する。

| 状態 | やること |
|---|---|
| A. `00_案件情報/engagement.json` が無い | 「新しい案件を作る」へ |
| B. 試算表か仕訳帳が `02_正規化データ/` に無い | 「資料を入れてもらう」へ |
| C. `plan_status` が `approved` でない | plan スキルで計画を作り、承認を受ける |
| D. 03_調書 に pass でも escalate でもない領域がある、または未実行の領域がある | run スキル |
| E. 送るべき依頼・督促がある（`pbc.py due` の結果が空でない） | request-mail スキル |
| F. 資料待ち（blocked）の領域が残っている | 状況を伝えて待つ。「資料が届いたら、このフォルダに置いて /tadori:start」と伝える。定期実行が未設定なら schedule スキルを提案 |
| G. 全領域が pass か escalate | finalize スキル |
| H. `案件台帳` の状態が「最終査閲待ち」 | 査閲メモの場所と、判断が要る事項の件数だけを伝える |

1回の実行で進めるのは、人の判断が要るところ（計画承認、最終査閲、メール送信の切替）まで。そこで止めて、何を決めてほしいかを短く伝える。

利用者が「どこまで進んだ？」と聞いたときは、判定だけして進めず、次の形で答える：
```
ABC商事 2026-03期
いまの段階：実行中（12領域中 9 pass、2 資料待ち、1 要判断）
あなたに決めてほしいこと：1件（売上の期間帰属）
資料待ち：2件（うち督促済み 1件）
```

## 新しい案件を作る（状態 A）
開いているフォルダの中身を見て、次のどちらかを判断する。
- 空か、他の案件フォルダ（`*期`）が並んでいる → ここを「案件を並べる親フォルダ」として扱う
- 試算表などの資料がそのまま置いてある → 1つ上を親フォルダにするか聞く

会話で聞くこと（分かっているものは聞かない）：
1. クライアント名
2. 決算期末日
3. 種別（法定監査／任意監査／内部監査／決算チェック）
4. 前期の案件フォルダがあるか

new-engagement スキルの手順でフォルダを作る。作ったら「作った案件フォルダを Cowork で開き直して、もう一度 /tadori:start」と伝える（他社のフォルダと同じ作業で開かないため）。

## 資料を入れてもらう（状態 B）
「試算表と仕訳帳（会計ソフトから出力したもの）を、このチャットに添付するか、このフォルダに置いてください」と伝える。届いたら intake スキルで取り込み、続けて状態判定に戻る。

## engagement.json を利用者に触らせない
依頼先のメールアドレス、担当者、重要性、メールの運用（下書き／送信）、資料の提出期限、依頼メールの署名は会話で聞き取り、このスキルか plan スキルが書き込む。承認後は書き換えられないので、承認の前に聞き漏れがないかを確かめる。

## メールの自動送信への切替
既定は下書き運用。利用者が「自動で送って」と言ったら、計画承認前なら plan スキルの承認時に、承認後なら reopen → 変更 → 再承認の手順を説明してから切り替える（hooks が承認済みの設定変更を止めるため）。
