# 調書の査閲基準

## ハードチェック（1件でもあれば点数に関係なく不合格）
| ID | 内容 |
|---|---|
| H1 | 手続の `evidence` が空、または参照先のファイル・ページ・セルに該当する記載がない |
| H2 | `script_runs` のコマンドを再実行した結果が調書の数字と違う |
| H3 | plan.json がこの領域に割り当てたアサーションのうち、どの手続でもカバーされていないものがある |
| H4 | `exceptions` があるのに、手続の結論か領域の結論で扱っていない |
| H5 | 「未了」の手続があるのに、領域の結論が問題なしになっている |
| H6 | 金額をスクリプトを通さずに書いている（`script_runs` が無いのに合計・差額がある） |
| H7 | 虚偽表示の金額・区分（事実／判断／推定）・影響勘定のいずれかが空 |
| H8 | `evidence` か `script_runs` が案件フォルダの外（`/tmp` などの一時フォルダ）のファイルを参照している |

## 採点（合計100点）
| 観点 | 配点 | 満点の状態 |
|---|---|---|
| 証拠の十分性 | 30 | アサーションごとに、外部証拠か独立した照合で裏付けがある。母集団の網羅性を確かめている |
| 手続の適切性 | 20 | リスクの高さに見合った手続と件数。サンプルの抽出方法と seed が記録されている |
| 結論の妥当性 | 20 | 結論が結果から導ける。別の説明（循環取引、期ズレなど）を検討している |
| 例外の扱い | 15 | 例外を1件ずつ原因まで追い、虚偽表示か否かを判断し、推定額を出している |
| 記載の追跡可能性 | 15 | 第三者が調書だけで同じ手続を再実施できる |

## 指摘の書き方
- `where`：手続 ID と項目名（例 `REV-03.result`）
- `problem`：何が足りないか、なぜ問題か
- `fix`：何をすれば直るか。資料が要るなら資料名と期間まで書く
- 重大＝結論が変わり得る、中＝証拠の補強が要る、軽微＝記載の補足
- 言い回しや体裁は指摘しない

## 人の判断に上げるもの（`needs_human`）
- 会計上の見積り（引当金、減損、繰延税金資産）の仮定が妥当かどうか
- 経営者の説明だけが根拠になっている判断
- 重要性の金額に近い差異
- 不正の兆候の可能性
