# 定期実行の設定

計画承認（ゲート1）が済んだ案件にだけ設定する。未承認なら止める。

## 作るタスク（案件ごとに2本）
| タスク名 | 頻度の目安 | 指示文 |
|---|---|---|
| `<クライアント>_<期> 受信処理` | 平日 1日2回（9時台・15時台） | 案件フォルダ `<場所>` を開き、`/tadori:start` を実行する（受領資料の取込と、充足した領域の再実行まで進む） |
| `<クライアント>_<期> 資料依頼` | 平日 1日1回（10時台） | 案件フォルダ `<場所>` を開き、`/tadori:start` を実行する（送るべき依頼と督促の処理まで進む） |

- スケジュールタスクの作成は Cowork の機能で行う。指示文には案件フォルダの場所を必ず書く（各タスクは独立したセッションで動き、この会話の内容を覚えていない）
- 時刻はちょうど0分を避ける（混雑で遅れるため）

## 注意
- Cowork のスケジュールタスクは、契約や設定によって「PC が起動していてアプリが開いている間だけ動く」場合と「クラウドで動き、PC のローカルフォルダは見えない」場合がある。後者で動かすなら、案件フォルダを共有ドライブ（Google Drive / SharePoint / Box など）に置き、コネクタ経由で読み書きする
- 下書き運用（`mail.mode` が `draft`）の間は、資料依頼タスクは下書きを作るだけ。人が下書きを見て送る
- 最終査閲（ゲート2）が済んだらタスクを止める
- クラウドで動く定期実行（Claude Code の `/schedule`）は、毎回リポジトリを取り直して動き、PC の案件フォルダは見えない。監査資料をリポジトリに置くことになるので使わない

## 短期の見張り（Claude Code の `/loop`）
「今日の午後、返信が来たらすぐ取り込んで」のように、数時間〜数日だけ見張りたいときに使う。数週間にわたる定期実行は上のスケジュールタスクで行う。

案件フォルダを開いた Claude Code で、利用者に次を入力してもらう（Claude が自分でループを始めない）。
```
/loop 資料の受信を見張る。毎回 /tadori:start を実行し、state.py next の keep_watching が false になったら止める
```
- 間隔は Claude が毎回 1分〜1時間で決める。受信処理なので 15〜30分より短くしない
- 止まる条件は `state.py next` の `keep_watching`。人の判断が要るところ（計画承認 C、最終査閲 H、予算超過 `ask-human`）と、資料がそろって最終確認に進めるとき（G）に false になる。条件が決まっているので、Claude の判断で途中でやめたり、際限なく回ったりしない
- セッションを開いている間だけ動く。7日で切れる。`--resume` で開き直しても戻らない
- Cowork で使えるかは確認できていない。Cowork では上のスケジュールタスクを使う
