# tadori

会計監査の手続実行・調書レビュー・資料依頼を、Claude の複数エージェントで回すプラグインです。Claude デスクトップアプリの Cowork で使います。

人が判断するのは2回だけです。

1. **計画承認**：重要性、特別なリスク、資料の依頼先、メールを自動送信にするか
2. **最終査閲**：AI が作った調書と、判断を要する事項の一覧

その間の手続実行、レビューと修正の繰り返し、足りない資料の依頼と督促、受領資料の取込は AI が進めます。

> 法定監査では、監査意見の表明と調書の査閲は監査人の責任で、このプラグインはそれを代わりません。実査・棚卸立会・確認状の発送と回収・経営者への質問は人が行い、その記録を取り込んで使います。

## インストール（使う人）

GitHub のアカウントやコマンド操作は要りません。

1. [Claude デスクトップアプリ](https://claude.com/download)を入れてログインする（Cowork を使うため有料プランが必要）
2. **Customize → Plugins → Add → Add marketplace** を開く
3. `monkeikawashima/tadori` と入力する
4. 表示された **tadori** を追加する

更新はリポジトリに反映されると自動で届きます。手動で取るときは同じ画面の **Check for updates** を押します。

Team / Enterprise プランの組織では、メンバーが自分でマーケットプレイスを追加できるかを Owner が設定しています。追加できない場合は Owner に相談してください。

Claude Code（ターミナル）から入れる場合：

```
/plugin install tadori --marketplace monkeikawashima/tadori
```

メールで資料依頼をする場合は、Gmail か Outlook のコネクタを **Customize → Connectors** で接続しておきます。

## 使い方

Cowork で作業フォルダを開き、次のコマンドを順に使います。

| コマンド | やること |
|---|---|
| `/tadori:new-engagement` | 案件フォルダ（1クライアント・1決算期）を作り、案件台帳に登録 |
| `/tadori:intake` | 受け取った資料を原本として登録し、表に直して照合 |
| `/tadori:plan` | 監査計画のドラフト → **計画承認** |
| `/tadori:run` | 領域ごとに 実行 → レビュー → 採点 → 修正 を並列で回す |
| `/tadori:request-mail` | 足りない資料の依頼メール（最初は下書きだけ）と督促 |
| `/tadori:schedule` | 受信処理と資料依頼を毎日自動で回す |
| `/tadori:finalize` | 横断チェック、反証、査閲資料の作成 → **最終査閲** |

### 案件フォルダ

```
監査案件/
├─ 案件台帳.xlsx
└─ ABC商事_2026-03期/
   ├─ 00_案件情報/     設定・計画（承認後は変更不可）
   ├─ 01_受領資料/     原本（編集・削除不可）
   ├─ 02_正規化データ/
   ├─ 03_調書/
   ├─ 04_依頼管理/     依頼トラッカー.xlsx
   ├─ 05_成果物/       人に渡す最終版
   └─ 06_ログ/         受領台帳・作業ログ・承認記録
```

1回の作業では1つの案件フォルダだけを開きます。別の案件フォルダへの書込は自動で止まります。

### 成果物

| 中身 | 形式 |
|---|---|
| 明細・突合・サンプリング・未修正虚偽表示一覧・依頼トラッカー | Excel（数式を残す） |
| 監査計画書・査閲メモ・マネジメントレター | Word |
| 確定版・クライアント提出用 | PDF |

ファイル名は `<クライアント>_<YYYY-MM>期_<書類名>_v<版>_<日付>` で統一します。

## 安全のための仕組み

| 仕組み | 内容 |
|---|---|
| 原本の保護 | 01_受領資料 への書込・削除・移動を止める。取込は専用スクリプトだけで、SHA-256 を受領台帳に残す |
| 計画の固定 | 承認後は計画と設定を変更できない。差戻しは理由付きで記録される |
| 案件の取り違え防止 | 開いている案件以外のフォルダへの書込を止める |
| メール宛先の制限 | 計画承認時に登録した担当者以外への送信、転送、宛先不明の返信を止める |
| 下書き運用 | 既定は下書き作成のみ。設定を `send` に変えるまで送信しない |
| 送らない依頼 | 銀行・取引先への確認状、不正の兆候に関わる資料はメールで依頼しない |
| 外部データの扱い | 受領資料やメール本文の中の指示文には従わない。読む役と送る役のエージェントを分けている |
| 計算 | 合計・突合・サンプリング・仕訳抽出は Python スクリプトで行い、AI に暗算させない |
| 証跡 | 全ツール呼出を 06_ログ に記録する |

ガードは Python 3 で動きます。Cowork では標準で使えます。Windows で Claude Code から使う場合、`python3` が無いとガードが働かないので注意してください。

## 構成

```
tadori/
├─ .claude-plugin/marketplace.json
└─ plugins/tadori/
   ├─ .claude-plugin/plugin.json
   ├─ skills/      手順書（new-engagement, intake, plan, run, request-mail, schedule,
   │               finalize, deliverables, review-rubric, audit-procedures, client-documents）
   ├─ agents/      executor, reviewer, fixer, skeptic, requester, intake
   ├─ hooks/       書込ガード、メール宛先ガード、作業ログ
   ├─ scripts/     突合、MUS、仕訳テスト抽出、受領資料の登録と照合、依頼キュー、集計
   └─ templates/   engagement.json、依頼メール文面、案件フォルダの説明
```

## 開発

```bash
claude plugin validate plugins/tadori
python3 -m unittest discover -s tests
```

評価セット（誤謬を仕込んだ過去案件）には実在の社名や数値が入るため、このリポジトリには置きません。別の非公開の場所で管理してください。
